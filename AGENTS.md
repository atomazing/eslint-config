# Agents Guidelines

## Commit Messages

This project uses [Conventional Commits](https://www.conventionalcommits.org/) enforced by commitlint (`@commitlint/config-conventional`).

### Subject Line

```
type: short description
```

- **type**: `feat`, `fix`, `ci`, `chore`, `docs`, `refactor`, `test`
- **description**: lowercase, imperative mood, no trailing period, max ~72 chars
- Examples:
  - `feat: update dependencies and adapt to eslint-plugin-react-refresh 0.5`
  - `fix: replace import/no-deprecated with type-aware deprecation checks`
  - `ci: bump pnpm/action-setup to v6`
  - `chore: cap eslint peer dependency to v9`

### Body

Always include a body for non-trivial changes. Write it in Markdown.

**Dependency update commits** — list each package with old and new version range. Regular dependencies come first, devDependencies come last under a `devDependencies:` label:

```
The changes include updates to:
- `package-name` (old-version -> new-version)
- `another-package` (^old-version -> ^new-version)

devDependencies:
- `dev-only-package` (^old-version -> ^new-version)

Additional notes about behavior changes or rationale if needed.
```

**Bug fix / rule change commits** — explain what was replaced and why:

```
Switch to `@typescript-eslint/no-deprecated` in import rules.
It uses TS type info and catches `.d.ts`/cross-file deprecations.

Closes #4
```

**Config / chore commits** — one sentence explaining the rationale:

```
Explicitly limit peer compatibility to ESLint 9 by changing the range to `>=9.29 <10`, preventing accidental installs with future major versions.
```

### Footer

Reference GitHub issues with `Closes #N` when applicable.

### Body line length

Max 200 characters per line (enforced by commitlint).

## GitHub Release Notes

Releases are auto-generated by `semantic-release` using the `conventionalcommits` preset. The base format groups commits under `### Features` and `### Bug Fixes` sections with a link to the commit.

After auto-generation, **manually edit the GitHub release** to add detail for notable changes. The enriched format looks like this:

### Structure

```markdown
## [X.Y.Z](compare-url) (YYYY-MM-DD)

### Features

* commit subject line ([shortsha](commit-url))
  - Bullet point expanding on what changed
  - Another detail, package version ranges: `old` -> `new`
  ⚠️⚠️⚠️ **Breaking / Notable Changes**:
    - [`rule-name`](link-to-docs) - What the rule enforces

### Bug Fixes

* commit subject line ([shortsha](commit-url)), closes [#N](issue-url)
  - What was changed and why (_italicized rationale_)
```

### When to enrich release notes

Always enrich when the release contains:

- **New ESLint rules** — list each new rule with a link to its docs page and a one-line description of what it enforces. Mark with ⚠️⚠️⚠️ **New Rules** or ⚠️⚠️⚠️ **New Unicorn Rules** etc.
- **Removed or replaced rules** — note the replacement and why the old rule was dropped (italicize the rationale).
- **Configuration changes requiring user action** — include a code block showing the new configuration.
- **Breaking behavior changes** — add a migration note in plain language.
- **Dependency updates** — add sub-bullets listing each package with `old-version -> new-version` range. Include only regular dependencies (not devDependencies — those are documented in the commit body only).

### Example — new rules (v3.8.0 style)

```markdown
* update lint dependencies for TypeScript 6 support ([1413c7b](url)), closes [#5](url)
  - Update `typescript-eslint` from ^8.57.0 to ^8.58.1
  - Update `eslint-plugin-unicorn` from 63.0.0 to ^64.0.0
  ⚠️⚠️⚠️ **New Unicorn Rules**:
    - [`consistent-template-literal-escape`](docs-url) - Enforce consistent escaping of `${` in template literals
    - [`no-useless-iterator-to-array`](docs-url) - Disallow unnecessary `.toArray()` calls on iterators
```

### Example — rule replacement with migration note (v3.7.0 style)

```markdown
* adapt to `eslint-plugin-react-refresh` 0.5 ([e5dbe7a](url))
  - `customHOCs` option was renamed to `extraHOCs`
  - Validation of HOCs calls is now more strict, you may need to add some HOCs to the `extraHOCs` option:
  ```ts
  {
    rules: {
      "react-refresh/only-export-components": ["warn", { "extraHOCs": ["someLibHOC", "observer"] }]
    }
  }
  ```
```

### Example — simple dependency update (v3.9.0 style)

```markdown
* update dependencies ([67909cf](url))
  - `eslint-plugin-react-hooks` (`^7.0.1` -> `^7.1.1`)
  - `globals` (`^17.4.0` -> `^17.5.0`)
  - `typescript-eslint` (`^8.58.1` -> `^8.59.0`)
```
